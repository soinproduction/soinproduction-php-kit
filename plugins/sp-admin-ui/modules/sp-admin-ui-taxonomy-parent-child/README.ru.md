# SP Admin UI Taxonomy Parent Child

Необязательный метабокс: один корневой термин через radio и несколько потомков через checkbox. Добавьте `sp-admin-ui-taxonomy-parent-child` в список подмодулей `sp-admin-ui` вместе с остальными нужными модулями. По умолчанию он выключен.

Для иерархической таксономии задайте `meta_box_cb => sp_taxonomy_parent_radio_child_checkboxes` либо передайте этот callback в `add_meta_box()` с аргументами `['taxonomy' => 'your_taxonomy']`. Имена таксономий и типы записей задаёт проект.

Сохранены callback и API `sp_taxonomy_parent_radio_child_checkboxes_save($post_id)`, имена полей `sp_parent_child_tax[taxonomy][parent]` и `sp_parent_child_tax[taxonomy][children][]`. Обработчик работает на `save_post` с приоритетом 10, проверяет контекст записи, права редактирования и назначения терминов, принадлежность иерархической таксономии типу записи. `0` очищает выбор; у корневого термина сохраняются только выбранные потомки его ветки. Автосохранения, ревизии и запросы без этих полей не меняют связи.

Потомки других корней отключаются и снимаются при переключении radio. Поддерживается любая глубина дерева. Отображаются существующие назначения; автоматической миграции данных нет. Стандартный редактор WordPress проверяет запрос сохранения до вызова хука; собственные обработчики должны проверять свои запросы самостоятельно.
