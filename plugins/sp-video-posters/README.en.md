# SP Video Posters

Adds poster-frame capture, existing-image selection and playback attributes to video attachments in the WordPress Media Library.

## Editor Workflow

Open a video attachment in Media Library:

1. Move the preview to the desired timestamp.
2. Capture the current frame or select an existing image.
3. Configure controls, muted, autoplay and loop.
4. Save the attachment.

The UI initializes only for video attachments and updates Media Library previews after an Ajax action completes.

## Data Model

- `_sp_video_poster_id` links the video to an image attachment.
- `_sp_video_poster_generated` marks frames generated by this module.
- `_sp_video_controls`, `_sp_video_muted`, `_sp_video_autoplay` and `_sp_video_loop` store playback flags.

When a generated poster is replaced or removed, the module can delete its old generated attachment without deleting manually selected images.

## Theme Integration

Use `sp_video_poster_id()` or `sp_video_poster_url()` in custom templates. The `display_media_attrs` filter adds the saved playback flags to the theme media renderer.

Autoplay normally requires muted playback in modern browsers. Always provide a poster or visual fallback for slow connections and reduced-data contexts.

## Hook and Asset Lifecycle

On admin requests the module registers Media Library field filters, three authenticated Ajax actions and inline CSS/JavaScript. `wp_enqueue_media()` provides the native image selector. The JavaScript scans attachment modals dynamically because WordPress reuses modal DOM and may render video fields after the initial page load.

On every request the `display_media_attrs` filter integrates playback flags with the theme's `display_image()`/media pipeline. Non-video media and invalid attachment IDs are returned unchanged.

## Poster Capture Flow

1. The browser seeks the `<video>` element to a selected timestamp.
2. JavaScript draws the current frame to a canvas and sends a PNG/JPEG/WebP data URL to `sp_video_preview_save_frame`.
3. The server verifies `upload_files` and nonce `sp_video_preview_action`.
4. Only `data:image/(png|jpeg|jpg|webp);base64` is accepted; decoded data is limited to 25 MB.
5. `wp_upload_bits()` writes a timestamped poster file.
6. `wp_insert_attachment()` creates a child image attachment and `wp_generate_attachment_metadata()` builds sizes.
7. `_sp_video_poster_generated = 1` marks ownership, then the video receives both `_sp_video_poster_id` and the standard featured-image relationship.

When capture replaces a previous generated poster, the old generated attachment is permanently deleted. An image selected manually is never marked generated and is therefore preserved.

## Ajax API

| Action | Required payload | Result |
| --- | --- | --- |
| `sp_video_preview_save_frame` | `nonce`, `attachment_id`, `image_data` | Creates and assigns a generated image. |
| `sp_video_preview_set_existing` | `nonce`, `attachment_id`, `poster_id` | Validates and assigns an existing image attachment. |
| `sp_video_preview_remove` | `nonce`, `attachment_id` | Removes poster meta and featured-image relation. |

All actions require an authenticated user with `upload_files`. Invalid video/image MIME returns `400`; authorization failures return `403`; upload/attachment creation failures return `500`.

## Playback Defaults

If a meta key has never been saved, defaults are: `controls=false`, `muted=true`, `autoplay=true`, `loop=true`. Saving the attachment writes an explicit `0` or `1` for every toggle.

The filter adds boolean `controls`, `muted`, `autoplay` and `loop` entries only when the media type is `video`. Templates that bypass the theme media helper must apply these values themselves.

## Public PHP API

```php
$poster_id  = sp_video_poster_id( $video );
$poster_url = sp_video_poster_url( $video, 'large' );
```

`$video` may be an attachment ID, URL or common ACF media array containing `ID`/`url`. Invalid/non-video input returns `0` or an empty string. The size argument first tries a generated WordPress image size and falls back to the original attachment URL.

## Cleanup and Troubleshooting

- Removing a poster through the UI clears the relation but does not delete a manually selected image.
- Replacing a captured frame cleans up the previous generated attachment when ownership meta is present.
- Deleting a video outside this module may leave manually assigned poster attachments; follow the site's media retention policy.
- **Capture button is disabled:** wait for video metadata; check CORS if the video URL is served from another origin.
- **Canvas capture is blank/blocked:** remote video bytes must allow canvas access; use **Choose image** instead.
- **Poster saves but frontend ignores it:** render through the theme media helper or call the public helper explicitly.
- **Autoplay fails:** browsers may require `muted`, `playsinline` and prior user interaction.
