# SP Archive Builder

ACF-поля/factories `archive_builder()` и `taxonomy_archive_builder()` настраивают архивы записей и терминов таксономий. Они используют единый модуль, одинаковый интерфейс в админке и общий frontend runtime: taxonomy filters, сортировка, количество элементов, pagination/load more/infinite scroll, empty state и confirm/reset.

```php
->addFields( archive_builder( 'archive', [
	'post_type'       => 'case_study',
	'filters_enabled' => 1,
	'per_page'        => 9,
	'pagination_type' => 'pagination',
] ) )
```

Оба поля поддерживают `source_mode => all|manual`. В Manual редактор выбирает записи через Smart Relationship или термины через Smart Taxonomy и выставляет порядок перетаскиванием. Фильтры и пагинация работают только внутри выбранного набора, а Sorting order скрывается, потому что manual-порядок является приоритетным.

```php
->addFields( taxonomy_archive_builder( 'industries', [
	'taxonomy'        => 'case_study_industry',
	'source_mode'     => 'all',
	'per_page'        => 9,
	'pagination_type' => 'infinity_scroll',
	'order_mode'      => 'az',
] ) )
```

Модуль также предоставляет семейство `sp_archive_*` для подготовки query, filters, cards и pagination. Объединённая версия поддерживает `term_scope`, режимы терминов `selected` / `children` / `parent`, группировку по первому фильтру, собственные подписи, `favorite_first`, confirm/reset и настраиваемые query args. Полный список опций и helpers приведён в `README.en.md`.

Для `per_page` поддерживаются положительное число, `-1` и строка `all`; два последних значения выводят все найденные записи без pagination. Шаблоны карточек и пустого состояния передаются как существующие пути относительно темы, без `.php`. WordPress учитывает дочернюю и родительскую тему; `THEME_DIR` не требуется. Стандартные папки UI проверяются только как необязательные варианты. Через `sp_archive_component_template` и `sp_archive_pagination_template` можно указать любой существующий шаблон темы; обязательной структуры папок нет.

Текущий язык Polylang/WPML сохраняется в серверной конфигурации и применяется также к AJAX-запросам. По умолчанию проверяется nonce `ajax_global`; для LDW или другой темы с отдельным nonce добавьте `add_filter('sp_archive_nonce_action', static fn(): string => 'sp_ajax_nonce');`.

## Фильтры по связанным записям

Для архивов записей доступна настройка `relationship_filters` в `archive_builder()`,
конфигурации ACF-поля или третьем аргументе `sp_archive_setup()`. Это настройка
разработчика, отдельной панели в редакторе ACF нет. Требуется `filters_enabled => 1`.

```php
sp_archive_setup($archive, 'php/cards/testimonial-card', [
    'relationship_filters' => [
        'testimonial_industry' => [
            'post_type' => 'markets',
            'reverse_field' => 'linked_testimonials',
            'alt_title' => 'short_title',
            'all_label' => 'Industries',
            'ui' => 'select',
        ],
        'testimonial_service' => [
            'post_type' => 'services',
            'reverse_field' => 'linked_testimonials',
            'alt_title' => 'short_title',
            'all_label' => 'Service',
            'ui' => 'select',
        ],
    ],
]);
```

Варианты — опубликованные записи указанного типа. `reverse_field` — метаполе
на выбранной записи Service/Market с массивом ID отзывов. Модуль
`sp-post-relationships` поддерживает эти обратные связи автоматически.
Несколько значений одного фильтра объединяются; разные фильтры пересекаются.
Результат также ограничивается ручной выборкой и фильтрами таксономий.
Сортировка, пагинация, Show More и `disable_empty` применяются к итоговой выборке.
Пустое пересечение возвращает ноль записей, ручной порядок сохраняется.

Значения опций и параметры URL — слаги (`post_name`) записей, например
`?testimonial_service=energy-audits-for-buildings`. Старые ссылки с ID также
принимаются и преобразуются в слаги в состоянии архива. Для названий опций
можно указать имя метаполя через `alt_title` отдельно для каждого фильтра
(по умолчанию `short_title`). Если значение отсутствует, пустое или не скалярное,
используется `get_the_title()`. Значение `'alt_title' => ''` отключает
альтернативное поле и всегда использует обычный заголовок записи.

Кнопка сброса требует и включённого `reset` в настройках ACF, и вызова
`sp_archive_reset()` в шаблоне секции: переключатель сам не добавляет разметку.

Вывод выполняет обычный `sp_archive_filters()`. Поддерживаются все пять видов
контролов. Можно задать `label` и `query_arg`; имена не должны совпадать с
параметрами сортировки, пагинации, другими фильтрами или служебными AJAX-полями.

**Нужна совместимая JS-логика темы:** при чтении конфигурации разрешите
`type === "relationship"` наряду с `taxonomy`, затем пересоберите JS:

```js
.filter(({name, taxonomy, type}) => name && (taxonomy || type === "relationship"))
```

Полный контракт, пример и команда интеграционного теста — в `README.en.md`.

## Настройки архива на странице (явное включение)

`editor_config => 1` у поля `archive_builder` позволяет редактору страницы выбрать тип записей, ограничения по терминам, порядок и состав фильтров посетителя (источник, подпись, вид), включить поиск. `allowed_post_types` ограничивает доступные типы; пустой список использует существующий список типов записей. Без включённого флага прежние интерфейс и формат сохранения не меняются.

Источники таксономий берутся у выбранного типа записей. Связи `sp-post-relationships` обнаруживаются через метаданные зарегистрированных ACF-полей. Дополнительные источники и прежние имена задаются серверной настройкой `editor_relationships`, сгруппированной по типу архива: `['case_study' => ['service' => ['post_type' => 'service', 'reverse_field' => 'linked_case_studies', 'label' => 'Services']]]`. Можно передать её через `acf/load_field` в проекте. Из браузера принимается только ID разрешённого источника, подпись и вид; переданные пользователем метаданные и типы источников игнорируются. Таксономии и связи можно перемешивать; `filter_order` сохраняет порядок, `label` задаёт подпись.

К прежним полям пагинации и ручного выбора в сохранённом значении добавляются `editor_configured`, `post_type`, `term_scope`, `editor_filters`, `search_enabled`. Фильтр хранит `source` (`taxonomy:slug` или `relationship:name`), `enabled`, `label`, `ui`, `terms_mode`. У прежних строк без `enabled` фильтр остаётся включённым. Выключение сохраняет подпись и вид, но исключает фильтр из runtime. Пустой список сохраняется явно и не заменяется значениями по умолчанию. Ручной выбор следует типу записей; ID других типов отбрасываются. `format_value()` проверяет настройки по серверному списку источников и возвращает обычную конфигурацию runtime.

Ограничения `term_scope` применяются независимо от наличия соответствующего фильтра посетителя; его выбор дополнительно сужает результат. Шаблон должен использовать форматированное значение поля, соблюдать `ui` и `label`, передавать пустой `search_arg`, если поиск выключен, и не перезаписывать фильтры в PHP. Для нескольких секций нужны разные URL-параметры. Старые значения без `editor_configured` используют настройки поля до следующего сохранения. Проект может адаптировать прежние значения через `acf/load_value`, сохраняя ключи полей и связи.

В Field Groups задаются доступные типы записей и фильтры. На странице редактор видит список с переключателями, выбором вида, стрелками порядка и раскрываемыми настройками строки. Разрешённые источники сохраняются в `editor_filter_sources[post_type]` (список ID источников); `editor_sources_configured => 1` отличает пустой разрешённый список от прежних defaults. Без флага доступны все обнаруженные источники. Ограничения `term_scope` не зависят от доступности фильтров посетителя. Технические параметры запросов находятся в закрытом Advanced.

Редактор страницы занимает всю доступную ширину поля: общие параметры, ограничения выборки и фильтры посетителя идут последовательно. Вид фильтра выбирается небольшими toggle-кнопками с одним активным значением. У выключенных фильтров управление остаётся видимым и недоступным, настройки сохраняются. Детали раскрываются внутри строки; кнопки порядка и раскрытия доступны с клавиатуры, анимации учитывают `prefers-reduced-motion`. Ручной режим показывает порядок выбранных записей и сохраняет прежнюю автоматическую сортировку. Оформление ограничено режимом `editor_config`; остальные архивные поля сохраняют прежний интерфейс.
